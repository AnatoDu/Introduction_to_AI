# Первое занятие: начинаем без технического квеста

Сегодня нужны собственный файл, маленький выполненный эксперимент и объяснение результата. Регистрация и установка программ не являются вступительным экзаменом.

## Как начать

1. Получите готовый пакет личного проекта и распакуйте его в свою папку. Если скачали весь репозиторий курса, скопируйте из него **всю** project_template в личное место, например ai_project. Внутри сразу есть workbooks, course_support, docs и README. Имя и расположение произвольные; папка курса рядом не требуется. Откройте Jupyter из корня проекта и тетрадь из workbooks.
2. Выберите свою папку, доступную для записи и видимую в Jupyter. Расположение и название свободные; материалы курса копируйте туда целиком.
3. Преподаватель покажет короткую проверку. Основные `01.1`/`01.2` работают — идём по ним. Не хватает библиотеки — открываем `workbooks/00. Старт без установки.ipynb`: только Python 3. Не запускается Jupyter — `docs/СТАРТ_БЕЗ_УСТАНОВКИ.html` в браузере, ответы в текстовом файле/на бумаге. Самостоятельное объяснение требуется в любом варианте.
4. На настройку не тратим всю пару. Если проблема не решена за несколько минут, переключаемся на резерв. Устанавливать пакеты всем одновременно сегодня не нужно.

## Сохранение сегодня

Сохраните тетрадь и README. Сделайте копию всей папки проекта в другом доступном месте: на личном носителе, другом устройстве или в подходящем хранилище. Откройте копию и проверьте последний ответ. Если перенос пока недоступен, согласуйте с преподавателем способ сохранения результата. Git-коммит сам по себе не создаёт копию на другом устройстве.

Если Git уже работает, можно сделать commit и bundle; это дополнительный путь первого дня. Обычная копия сегодня достаточна. Bundle содержит только коммиты, не несохранённый текст и не все файлы на диске. В общедоступном хранилище не оставляйте пароли, ключи и личные данные.

## К следующему занятию — GitHub у всех

К следующему занятию:

- зарегистрироваться именно на GitHub, подтвердить почту и проверить вход дома/на своём устройстве;
- создать отдельный репозиторий для этого курса;
- добавить README: тема или вопрос проекта, результат первого блока, один следующий шаг;
- загрузить весь личный проект, включая course_support с учебными данными, и передать преподавателю ссылку; приватный репозиторий допустим, но доступ преподавателю надо предоставить;
- убедиться, что в публикации нет лишних данных. Исходные личные фото без проверки не выкладывать.

Если дома Git пока не настроен, для первого результата можно использовать сайт GitHub → Add file → Upload files. Это сохраняет версии на GitHub, но не переносит историю локального Git; нормальный Git-workflow освоим отдельно. Не загружайте всю папку курса, `.git`, `_teacher`, окружение и большие исходные видео.

Если регистрация не удалась, до следующего занятия сообщите конкретную проблему и принесите файл с работой. Результат не пропадает, но препятствие решаем, а не переносим до экзамена. Другой сервис не заменяет GitHub по умолчанию.

На общем компьютере не сохраняйте пароль/токен, не входите в Git через менеджер учётных данных. Сегодня вход вообще не нужен. Если позднее необходим веб-вход, используйте приватное окно, выйдите и закройте его; загруженные файлы на диске при этом сами не удаляются.

[Официальная инструкция создания аккаунта](https://docs.github.com/en/account-and-profile/how-tos/account-management/creating-an-account-on-github).

## Минимум в конце блока

Изменённый пример + объяснение одной ошибки/ограничения + карточка проекта + проверенная копия. Расширения и просмотр фильмов не обязательны. После блока напишите три строки: что получилось; что осталось непонятным; что сделаю до следующей встречи.

## Не нужно заполнять весь шаблон за одну пару

Сегодня работаем в workbooks и заполняем несколько строк README. Папки notebooks, data, reports и паспорт пригодятся позже; пустые поля шаблона сегодня допустимы. В тетрадях места «ваш код здесь» нужно заполнить перед запуском зависимых ячеек: Run All незаполненной тетради может остановиться на отсутствующей переменной. Для сдачи запускаем сверху вниз уже выполненную работу.

Полные правила: [оценивание](ОЦЕНИВАНИЕ.md), [проект](ПРОЕКТ.md), [сдача и связь](СДАЧА.md). Критерии первой лабораторной относятся к нескольким занятиям; сегодня требуется только результат первого блока.
