# ЛР3. Очистка данных

Цель — получить из исходных данных проверенную рабочую таблицу и объяснить принятые решения.
Работа продолжает проект после сбора данных. Если собственного подходящего набора пока нет,
можно использовать предоставленный синтетический `course_support/data/preprocessing/requests_raw.csv`.
Сначала прочитайте его `SOURCE.md`. Объём набора и число найденных ошибок сами по себе не оцениваются.

## Что сделать

1. Сохраните неизменённый исходник в своей папке данных. Укажите источник и смысл одной строки.
2. Проверьте типы, пропуски, дубликаты, ключи и разумные для задачи диапазоны. Запишите найденные проблемы и то, чего не обнаружили.
3. Выполните необходимые преобразования по шагам. Различайте ноль и неизвестность; не удаляйте выброс только потому, что он большой. Спорные записи можно сохранить отдельно с объяснением.
4. Добавьте проверки, которые относятся к вашему набору: ключ, тип, диапазон или другое содержательное правило. На маленьком отдельном примере покажите, что проверка замечает нарушение. Исходные данные ради этого не портят.
5. Сохраните очищенные данные и сравните число строк до/после. Объясните каждое удаление, объединение или заполнение. Если изменений не требуется, обоснуйте это диагностикой.
6. Перезапустите ядро и выполните обработку из исходника. Результат должен воспроизводиться без переменных из другой тетради и без репозитория преподавателя.

Не требуется специально находить пять дефектов, добавлять ненужные преобразования или искусственно
соединять таблицы ради `merge`. Если в проекте нет подходящего случая, соответствующий навык покажите
на коротком предоставленном примере отдельно от своего чистого набора.

## Что передать

- Тетрадь или скрипт с последовательной обработкой, объяснениями и проверками.
- Доступный исходник и очищенную копию либо точную инструкцию получения исходника, если его нельзя распространять.
- Краткое описание запуска, источника, изменений числа строк и оставшихся ограничений.

Собственные файлы храните отдельно от `course_support`, например в `workbooks`, `data` и `reports`.
Ваш проект не должен импортировать учебные проверки `checks.py`: содержательные проверки данных
пишутся в вашей работе. GitHub необязателен, файлы или архив оцениваются наравне со ссылкой.

## Оценивание и срок

**20 баллов**, пять критериев по 4 балла: диагностика; типы и пропуски; дубли и выбросы;
содержательные проверки; воспроизводимость и объяснение изменений.
Полные формулировки — [ОЦЕНИВАНИЕ.md](ОЦЕНИВАНИЕ.md), порядок передачи — [СДАЧА.md](СДАЧА.md).
Новых баллов за активность, число проверок, коммиты или скорость выполнения нет.

SQL из блока 06 — отдельная учебная практика, не дополнительное условие этой лабораторной.
Срок сдачи и общий срок доработки объявляет преподаватель для группы. Доработка разрешена по общим правилам.
Если использовали ИИ-помощь, укажите, в чём она состояла; ход работы и выбор решений объясняете вы.
